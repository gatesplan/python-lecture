2 [출력 예측 - >= vs > (결합성)]
아래는 중위식을 후위식으로 바꾸는 코드다. "5 - 3 - 1"을 넣을 때:
expr = "5 - 3 - 1" prec = {'+': 1, '-': 1, '*': 2, '/': 2} s = [] out = [] for t in expr.split(): if t in prec: while len(s) > 0 and prec[s[-1]] >= prec[t]: out.append(s.pop()) s.append(t) else: out.append(t) while len(s) > 0: out.append(s.pop()) print(" ".join(out))
(1) 지금 코드(>=)의 출력은?
(2) >= 를 > 로 바꾸면 출력은?
3 [출력 예측 - pop 순서 (비가환)]
아래는 후위식 계산 코드다.
expr = "10 3 -" s = [] for t in expr.split(): if t in ('+', '-', '*', '/'): b = s.pop() a = s.pop() if t == '+': s.append(a + b) elif t == '-': s.append(a - b) elif t == '*': s.append(a * b) else: s.append(a / b) else: s.append(int(t)) print(s.pop())
(1) "10 3 -" 을 계산하면 출력은?
(2) b = s.pop() 과 a = s.pop() 순서를 뒤바꾸면 어떤 입력에서 답이 틀릴까?

n = 13 front = '' while n > 0: front = str(n % 2) + front # 앞에 붙임 n //= 2 n = 13 back = '' while n > 0: back = back + str(n % 2) # 뒤에 붙임 n //= 2 print(front) print(back)

8 [출력 예측 - while n>0 이 놓치는 값]
같은 진법 변환 코드를 n=13과 n=0으로 각각 실행한다.
n = 13 s = '' while n > 0: s = str(n % 2) + s n //= 2 print(repr(s)) n = 0 s = '' while n > 0: s = str(n % 2) + s n //= 2 print(repr(s))
(1) n=13 일 때 출력은?
(2) n=0 일 때 출력은?

정답

1 [출력 예측 - 단락 평가]
(1) True - 왼쪽 len==0이 참이라 s.pop()은 실행조차 안 됨.
(2) IndexError - 왼쪽 s.pop()을 먼저 실행해 빈 리스트 pop. 빈 검사를 먼저 둬야 안전하다.
2 [출력 예측 - >= vs > (결합성)]
(1) 5 3 - 1 - -> (5-3)-1 = 1 (좌결합, 올바름).
(2) 5 3 1 - - -> 5-(3-1) = 3 (틀림). 같은 우선순위끼리는 왼쪽 것을 먼저 꺼내야 왼쪽부터 계산된다.
3 [출력 예측 - pop 순서 (비가환)]
(1) 7.
(2) 3 - 10 = -7 로 틀린다. 단 10 3 + 는 순서를 바꿔도 13으로 같다. +, *는 교환법칙이 성립하고 -, /만 순서에 영향받는다.
4 [빈칸 - 호너 방식]
b (또는 3). 한 자리 꺼낼 때마다 값에 진법을 곱하고 새 자릿수를 더한다. 34 = ((1*3+0)*3+2)*3+1.
5 [출력 예측 - 앞/뒤 붙이기]
(1) 1101 (정답).
(2) 1011 (뒤집힘). 나머지는 낮은 자리부터 나오므로, 앞에 붙이면 스택에 쌓았다 꺼낸 것과 같은 효과가 난다.
6 [출력 예측 - 스택 뒤집기]
KCATS. push한 순서의 역순으로 pop된다(LIFO). 전부 넣었다 전부 빼면 뒤집기가 된다.
7 [출력 예측 - 큐 회전]
[3, 4, 1, 2]. 1이 뒤로, 그다음 2가 뒤로 간다. 카드 버리기 문제의 '다음 카드를 맨 아래로'가 이 동작이다.
8 [출력 예측 - while n>0 이 놓치는 값]
(1) '1101'.
(2) '' (빈 문자열). while n>0이 처음부터 거짓이라 루프를 한 번도 안 돈다. n==0이면 '0'을 따로 처리해야 한다.
