9. 학습자료 - 스택과 큐, 정렬 알고리즘

자료구조 두 가지와 정렬 알고리즘 다섯 가지를 정리한다. 코드는 클래스를 쓰지 않고, 변수 이름은 교과서와 시험 문제에서 쓰는 짧은 형태를 그대로 따른다. 정렬은 전부 같은 리스트 [3, 6, 5, 8, 2]로 추적한다.

1. 스택

나중에 넣은 것이 먼저 나오는 구조다. 넣고 빼는 곳이 한쪽 끝뿐이다. 이 성질을 후입선출(LIFO, Last In First Out)이라고 부른다.

리스트로 바로 쓰기

파이썬에서는 스택을 위해 따로 만들 것이 없다. 리스트가 이미 스택이다.

S = [] S.append(10) S.append(20) S.append(30) print(S) # [10, 20, 30] print(S.pop()) # 30 print(S[-1]) # 20 print(len(S)) # 2

함수로 이름을 붙인 형태

append와 pop을 그대로 써도 되지만, 시험 문제에서는 아래처럼 함수 이름을 붙인 형태가 자주 나온다. 하는 일은 위와 똑같다.

S = [] def push(x): S.append(x) def pop(): return S.pop() def top(): return S[-1] def empty(): return len(S) == 0
주의. 비어 있는 스택에서 pop()이나 S[-1]을 하면 IndexError가 난다. 그래서 반복문 조건에 while len(S) > 0: 또는 while S: 를 먼저 두는 경우가 많다.

스택이 쓰이는 곳: 괄호 짝 검사, 십진수를 이진수로 바꾸기, 깊이우선탐색(DFS), 함수 호출 기록.

2. 큐

먼저 넣은 것이 먼저 나오는 구조다. 넣는 곳과 빼는 곳이 반대쪽이다. 이 성질을 선입선출(FIFO, First In First Out)이라고 부른다.

리스트로 바로 쓰기

Q = [] Q.append(10) Q.append(20) Q.append(30) print(Q) # [10, 20, 30] print(Q.pop(0)) # 10 print(Q[0]) # 20 print(len(Q)) # 2

dequeueQ.pop(0)맨 앞에서 빼서 돌려준다
frontQ[0]맨 앞을 보기만 한다
emptylen(Q) == 0비었는지 확인한다

3. 버블 정렬

이웃한 두 개를 비교해서 순서가 틀렸으면 자리를 바꾼다. 이것을 왼쪽 끝부터 오른쪽 끝까지 한 번 훑으면, 가장 큰 값이 맨 뒤로 밀려나 확정된다. 이 훑기를 반복한다.

def f(A): n = len(A) for i in range(n): for j in range(n-i-1): if A[j] > A[j+1]: A[j], A[j+1] = A[j+1], A[j] A = [3, 6, 5, 8, 2] f(A) print(A) # [2, 3, 5, 6, 8]

코드 읽기

  • i - 몇 번째 훑기인지. 훑기 한 번을 흔히 "패스"라고 부른다.
  • j - 지금 비교하는 왼쪽 원소의 위치. 오른쪽은 항상 j+1이다.
  • range(n-i-1) - 뒤쪽 i개는 이미 확정됐으므로 볼 필요가 없다. 그래서 훑는 범위가 매번 하나씩 줄어든다. -1이 붙는 이유는 A[j+1]을 읽어야 해서, j가 마지막 칸까지 가면 안 되기 때문이다.
  • A[j], A[j+1] = A[j+1], A[j] - 두 값을 맞바꾸는 문장이다. 임시 변수 없이 한 줄로 쓴다.

동작 추적

훑기 한 번이 끝날 때마다 오른쪽 끝에서부터 값이 하나씩 확정된다. 확정된 부분에 밑줄을 그어 표시했다.

횟수와 복잡도

이 예에서 비교는 4+3+2+1+0 = 10회, 자리 바꾸기는 5회 일어났다. 일반적으로 비교 횟수는 n(n-1)/2 이므로 시간복잡도는 O(n^2)이다.

최선의 경우. 위 코드는 입력이 이미 정렬돼 있어도 비교 횟수가 줄지 않는다. 훑는 동안 한 번도 바꾸지 않았다면 이미 정렬된 것이므로, 아래처럼 조기 종료를 넣으면 최선의 경우가 O(n)이 된다.
def f(A): n = len(A) for i in range(n): c = False for j in range(n-i-1): if A[j] > A[j+1]: A[j], A[j+1] = A[j+1], A[j] c = True if not c: break

4. 선택 정렬

아직 정렬되지 않은 부분에서 가장 작은 값을 찾아, 그 부분의 맨 앞과 자리를 바꾼다. 이것을 앞에서부터 반복한다.

def f(A): n = len(A) for i in range(n-1): m = i for j in range(i+1, n): if A[j] < A[m]: m = j A[i], A[m] = A[m], A[i] A = [3, 6, 5, 8, 2] f(A) print(A) # [2, 3, 5, 6, 8]

코드 읽기

  • i - 지금 값을 확정하려는 자리.
  • m - 지금까지 찾은 최솟값의 위치다. 값이 아니라 인덱스를 기억한다는 점이 중요하다. 자리를 바꾸려면 위치를 알아야 하기 때문이다.
  • m = i - 일단 맨 앞이 최솟값이라고 가정하고 시작한다.
  • range(i+1, n) - i 자리 다음부터 끝까지 훑으며 더 작은 값이 있는지 본다.
  • range(n-1) - 마지막 하나는 남은 것이 그것뿐이라 저절로 제자리다. 그래서 n-1번만 돈다.

동작 추적

i=2일 때는 m이 2로 나와 자기 자신과 바꾸게 된다. 즉 아무 변화가 없는 교환도 그대로 실행된다.

횟수와 복잡도

비교는 버블 정렬과 똑같이 10회지만, 자리 바꾸기는 4회뿐이다. 훑기 한 번에 교환이 딱 한 번만 일어나기 때문이다.

시간복잡도는 최선, 평균, 최악이 모두 O(n^2)이다. 이미 정렬된 리스트가 들어와도 최솟값을 찾으려면 남은 원소를 전부 확인해야 하므로 비교 횟수가 줄어들 여지가 없다.

5. 삽입 정렬

앞부분은 이미 정렬돼 있다고 보고, 그 다음 값 하나를 앞부분의 알맞은 자리에 끼워 넣는다. 끼워 넣을 자리를 만들기 위해, 더 큰 값들을 뒤로 한 칸씩 민다.

def f(A): n = len(A) for i in range(1, n): k = A[i] j = i - 1 while j >= 0 and A[j] > k: A[j+1] = A[j] j -= 1 A[j+1] = k A = [3, 6, 5, 8, 2] f(A) print(A) # [2, 3, 5, 6, 8]

코드 읽기

  • k - 지금 끼워 넣으려는 값. 뒤로 미는 작업 때문에 원래 자리가 덮어써지므로, 미리 따로 보관해 둔다.
  • j - 앞부분을 뒤에서부터 거슬러 보는 위치.
  • while j >= 0 and A[j] > k - 조건이 두 개다. 앞쪽 끝을 넘어가지 않아야 하고(j >= 0), 그 값이 k보다 커야(A[j] > k) 뒤로 민다.
  • A[j+1] = k - 반복이 끝난 지점의 바로 뒤가 k의 자리다. while이 끝났다는 것은 A[j]가 k보다 작거나 같다는 뜻이므로, k는 그 다음 칸에 들어간다.
  • range(1, n) - i가 1부터 시작한다. 원소가 하나뿐인 앞부분(A[0])은 이미 정렬된 상태로 볼 수 있기 때문이다.

복잡도

  • 최선 O(n) - 이미 정렬된 리스트가 들어오면 A[j] > k가 매번 처음부터 거짓이라 while 안으로 한 번도 들어가지 않는다. 바깥 for만 n-1번 돈다.
  • 최악 O(n^2) - 역순으로 정렬된 리스트가 들어오면 매번 앞부분 전체를 밀어야 한다.
  • 평균 O(n^2)

거의 정렬된 리스트에서는 기초 정렬 세 가지 중 가장 빠르다.

6. 병합 정렬

리스트를 반으로 나눈다. 각각을 같은 방법으로 정렬한다. 정렬이 끝난 두 리스트를 하나로 합친다. 자기 자신을 다시 부르는 재귀 구조다.

def f(A): if len(A) <= 1: return A m = len(A) // 2 L = f(A[:m]) R = f(A[m:]) return merge(L, R) def merge(L, R): res = [] i = j = 0 while i < len(L) and j < len(R): if L[i] <= R[j]: res.append(L[i]) i += 1 else: res.append(R[j]) j += 1 res.extend(L[i:]) res.extend(R[j:]) return res print(f([3, 6, 5, 8, 2])) # [2, 3, 5, 6, 8]

코드 읽기

  • if len(A) <= 1: return A - 재귀의 종료 조건이다. 원소가 하나이거나 없으면 더 나눌 것도 없고 이미 정렬된 상태다.
  • m = len(A) // 2 - 가운데 위치. A[:m]이 앞쪽, A[m:]이 뒤쪽이다.
  • merge(L, R) - 정렬된 두 리스트를 합치는 함수. L과 R 각각 맨 앞부터 보면서 작은 쪽을 꺼내 res에 붙인다.
  • i, j - L과 R에서 지금 보고 있는 위치.
  • res.extend(L[i:]) - 한쪽이 먼저 바닥나면 다른 쪽에 남은 것은 이미 정렬돼 있으므로 그대로 뒤에 붙인다. 둘 중 한쪽은 항상 빈 리스트라 두 줄 다 써도 문제없다.
  • 이 코드는 원래 리스트 A를 바꾸지 않는다. 새 리스트를 만들어 돌려준다. 그래서 f(A)만 부르지 말고 결과를 받아 써야 한다.

동작 추적

나누는 과정과 합치는 과정이다. 안쪽으로 들어갈수록 들여쓰기가 깊어진다.

나누기 [3, 6, 5, 8, 2] [3, 6] [3] [6] [5, 8, 2] [5] [8, 2] [8] [2] 합치기 (안쪽에서 바깥쪽 순서로) merge([3], [6]) = [3, 6] merge([8], [2]) = [2, 8] merge([5], [2, 8]) = [2, 5, 8] merge([3, 6], [2, 5, 8]) = [2, 3, 5, 6, 8]

복잡도

반으로 나누는 깊이가 log n이고, 각 깊이마다 전체 n개를 훑어 합친다. 따라서 O(n log n)이다. 최선, 평균, 최악이 모두 같다. 입력이 어떤 상태든 나누는 방식이 항상 절반으로 똑같기 때문이다.

대신 합칠 때 새 리스트 res를 만들기 때문에 추가 메모리가 필요하다. 기초 정렬 세 가지는 원래 리스트 안에서 자리만 바꾸므로 추가 메모리가 거의 들지 않는다.

7. 퀵 정렬

기준값을 하나 정한다. 기준값보다 작은 것, 같은 것, 큰 것으로 나눈다. 작은 쪽과 큰 쪽을 각각 같은 방법으로 정렬한 뒤 순서대로 이어 붙인다. 이것도 재귀 구조다.

def f(A): if len(A) <= 1: return A p = A[len(A)//2] L = [x for x in A if x < p] M = [x for x in A if x == p] R = [x for x in A if x > p] return f(L) + M + f(R) print(f([3, 6, 5, 8, 2])) # [2, 3, 5, 6, 8]

코드 읽기

  • p - 기준값(피벗). 여기서는 가운데 자리의 값을 쓴다. 첫 원소나 마지막 원소를 쓰는 교과서도 있다.
  • L, M, R - 기준값보다 작은 것, 같은 것, 큰 것을 모은 리스트. 리스트 컴프리헨션으로 한 줄씩 만든다.
  • M을 따로 두는 이유 - 기준값과 같은 값이 여러 개 있을 수 있다. 이것들은 이미 제자리가 정해졌으므로 다시 정렬할 필요가 없다.
  • f(L) + M + f(R) - 작은 쪽, 기준값, 큰 쪽 순서로 이어 붙이면 전체가 정렬된다.
  • 병합 정렬과 마찬가지로 원래 리스트를 바꾸지 않고 새 리스트를 돌려준다.

동작 추적

f([3, 6, 5, 8, 2]) p = 5 L = [3, 2] M = [5] R = [6, 8] f([3, 2]) p = 2 L = [] M = [2] R = [3] f([]) -> [] f([3]) -> [3] 결과: [] + [2] + [3] = [2, 3] f([6, 8]) p = 8 L = [6] M = [8] R = [] f([6]) -> [6] f([]) -> [] 결과: [6] + [8] + [] = [6, 8] 결과: [2, 3] + [5] + [6, 8] = [2, 3, 5, 6, 8]

복잡도

  • 평균 O(n log n) - 기준값이 대체로 가운데쯤 값이면 리스트가 매번 절반씩 줄어든다.
  • 최악 O(n^2) - 기준값이 매번 가장 작은 값 또는 가장 큰 값으로 잡히는 경우다. 그러면 한쪽이 비고 다른 쪽만 하나 줄어들어, 나누는 깊이가 n이 된다.
최악이 언제 생기나. 기준값을 첫 원소로 잡는 코드에 이미 정렬된 리스트를 넣으면 매번 최솟값이 기준값이 되어 최악이 된다. 위 코드처럼 가운데 값을 쓰면 이 경우는 피할 수 있지만, 다른 입력에서 최악이 생길 수 있다는 점은 같다.

최악이 O(n^2)인데도 실제로 널리 쓰이는 이유는, 평균적으로 빠르고 병합 정렬과 달리 별도의 큰 보조 리스트를 쓰지 않는 구현이 가능하기 때문이다.

비교 횟수가 같아도 실제 데이터를 옮기는 양은 다르다. 선택 정렬은 훑기 한 번에 교환이 한 번뿐이라, 옮기는 비용이 큰 상황에서 유리하다.

같은 값의 순서가 유지되는가

값이 같은 원소가 둘 있을 때, 정렬한 뒤에도 원래 앞뒤 순서가 그대로 남는 정렬을 안정 정렬이라고 한다. 예를 들어 이름과 점수를 함께 정렬할 때, 점수가 같은 사람들의 원래 순서를 지키고 싶다면 안정 정렬이 필요하다.

정렬안정이유
버블예조건이 A[j] > A[j+1]이라 같으면 바꾸지 않는다
선택아니오멀리 떨어진 두 자리를 바로 맞바꾸면서 사이에 있던 같은 값의 순서가 흐트러진다
삽입예조건이 A[j] > k라 같으면 더 밀지 않고 뒤에 놓는다
병합예merge 조건이 L[i] <= R[j]라 같으면 앞쪽 L을 먼저 꺼낸다
퀵구현에 따라위 코드는 순서가 유지되지만, 리스트 안에서 자리를 맞바꾸는 방식의 퀵 정렬은 유지되지 않는다
정리. 버블, 선택, 삽입은 반복문 두 겹으로 만들며 O(n^2)이다. 병합과 퀵은 재귀로 리스트를 나누어 O(n log n)에 가깝다. 파이썬에서 실제로 정렬할 때는 A.sort()나 sorted(A)를 쓰면 되지만, 이 다섯 가지를 직접 만들어 보는 이유는 같은 문제를 푸는 방법이 여러 가지이고 그 효율이 서로 다르다는 것을 확인하기 위해서다.

1 2 5
바깥 반복이 range(n-1)이라 i는 0, 1, 2까지만 돈다. 각 단계에서 확정된 값 1, 2, 5가 순서대로 출력된다. 마지막 8은 저절로 제자리가 되지만 print를 거치지 않으므로 출력되지 않는다.
4-2
(가) i   (나) A[j] < A[m]   (다) A[i], A[m] = A[m], A[i]
(가)는 일단 맨 앞자리를 최솟값 위치로 가정하고 시작한다는 뜻이다.
4-3
남은 부분에서 가장 작은 값을 찾으려면, 그 부분의 원소를 하나도 빠뜨리지 않고 전부 확인해야 한다. 리스트가 이미 정렬돼 있는지 여부는 다 확인해 보기 전에는 알 수 없다. 그래서 비교 횟수는 입력 상태와 무관하게 항상 n(n-1)/2로 같고, 최선과 최악이 모두 O(n^2)이다.
5-1
(가) A[i]   (나) j >= 0 and A[j] > k   (다) A[j+1] = k
(가)에서 값을 미리 빼 두지 않으면, 뒤로 미는 과정에서 그 자리가 덮어써져 값을 잃는다.
5-2
i=1 끝: [1, 4, 3, 2]  /  i=2 끝: [1, 3, 4, 2]  /  i=3 끝: [1, 2, 3, 4]
i=3에서는 k=2를 두고 4와 3을 뒤로 민 뒤, 1보다는 크므로 그 다음 칸에 2를 넣는다.
5-3
최선은 입력이 이미 오름차순으로 정렬돼 있을 때다. 이때 A[j] > k가 매번 처음부터 거짓이라 while 안으로 한 번도 들어가지 않는다. 각 i마다 비교를 한 번씩만 하고 바깥 for만 n-1번 돌아 O(n)이 된다.
최악은 입력이 내림차순일 때다. 끼워 넣을 값이 매번 앞부분 전체보다 작아서 앞부분을 전부 뒤로 밀어야 하고, 미는 횟수가 1 + 2 + ... + (n-1)이 되어 O(n^2)이 된다.
