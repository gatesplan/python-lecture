5. 복습 - 문법과 알고리즘 핵심

1부는 문법, 2부는 스택/큐/재귀. 실행 전에 결과를 먼저 예측해서 적고, 정답은 뒷장에서 확인.

1. 변수와 타입 (형변환)

3과 "3"은 다른 것이다. int / float / str / bool.

1-1 [출력 예측]
각 줄의 출력을 예측하라. 에러가 나는 줄도 있다.
a = 3 b = "3" print(a + a) # (1) print(b + b) # (2) print(int(b) + a) # (3) print(str(a) + b) # (4) print(a + b) # (5)
(1)~(5)를 순서대로 적어라.
1-2 [출력 예측 - 나눗셈 세 가지]
/, //, % 의 차이를 확인한다.
print(7 / 2) # (1) print(7 // 2) # (2) print(7 % 2) # (3) print(type(7 / 2)) # (4)
(1)~(4)를 적어라.
1-3 [빈칸]
input()이 준 문자열을 숫자로 써야 한다. 빈칸을 채워라.
s = "42" n = ____(s) print(n + 8) # 50

0번부터 센다. 마지막은 -1. 슬라이싱 arr[a:b]는 b를 포함하지 않는다.

2-2 [출력 예측 - 슬라이싱]

(1)~(4)를 적어라.
2-3 [출력 예측 - 리스트 메서드]
각 줄 실행 후 arr의 상태를 추적하라.

(1)~(3)을 적고, arr = arr.sort() 라고 쓰면 왜 안 되는지 설명하라.

5. 함수 (return의 의미)

print는 화면에 찍는 것, return은 값을 돌려주는 것.

5-1 [출력 예측 - print vs return]
두 함수의 차이를 보라.
def f1(n): print(n * 2) def f2(n): return n * 2 a = f1(5) b = f2(5) print("a =", a) # (1) print("b =", b) # (2) print(f2(5) + 1) # (3) print(f1(5) + 1) # (4)
화면에 찍히는 것을 순서대로 모두 적어라.
5-2 [출력 예측 - return은 즉시 종료]
각 호출에서 화면에 무엇이 찍히나?
def f(n): if n > 0: return "양수" print("여기 지나감") return "음수 또는 0" print(f(5)) print(f(-5))
출력을 순서대로 적어라.
5-3 [빈칸 - 조기 반환]
in을 쓰지 말고, arr에 x가 있으면 True 없으면 False를 반환하라.
def contains(arr, x): for v in arr: if v == x: ____ # (1) ____ # (2) print(contains([1,2,3], 2)) # True print(contains([1,2,3], 9)) # False
(1), (2)를 채우고, (2)의 들여쓰기가 왜 중요한지 쓰라.

7. 스택 (리스트로 직접)

LIFO. 넣기 s.append(x), 꺼내기 s.pop(), 맨 위 보기 s[-1].

7-1 [출력 예측 - 상태 추적]
스택의 상태를 종이에 그려가며 추적하라.
s = [] s.append(1) s.append(2) s.append(3) print(s.pop()) # (1) s.append(4) print(s.pop()) # (2) print(s.pop()) # (3) print(s) # (4)
(1)~(4)를 적어라.
7-2 [빈칸 - 괄호 검사]
가장 대표적인 스택 문제다. 빈칸 세 개를 채워라.
expr = "(()())" s = [] ok = True for ch in expr: if ch == '(': s.____(ch) # (1) elif ch == ')': if len(s) == 0: ok = False break s.____() # (2) if ____: # (3) ok = False print(ok)
(1)~(3)을 채워라.
이 코드가 "(()" 와 "())" 를 각각 어느 지점에서 걸러내는지 쓰라.
7-3 [출력 예측 - 후위식 계산]
pop 두 번의 순서에 주의하라.
expr = "5 1 2 + 4 * + 3 -" s = [] for t in expr.split(): if t in ('+', '-', '*', '/'): b = s.pop() # 오른쪽 피연산자 a = s.pop() # 왼쪽 피연산자 if t == '+': s.append(a + b) elif t == '-': s.append(a - b) elif t == '*': s.append(a * b) else: s.append(a / b) else: s.append(int(t)) print(s.pop())
출력을 적어라.
b와 a를 꺼내는 두 줄의 순서를 바꾸면 어떤 연산에서 답이 틀리는가?

8. 큐 (리스트로 직접)

FIFO. 넣기 q.append(x), 꺼내기 q.pop(0).

8-1 [출력 예측 - 상태 추적]
7-1과 같은 순서로 넣고 뺀다.
q = [] q.append(1) q.append(2) q.append(3) print(q.pop(0)) # (1) q.append(4) print(q.pop(0)) # (2) print(q) # (3)
(1)~(3)을 적고, 스택이었다면 무엇이 나왔을지도 쓰라.
8-2 [빈칸 - 카드 버리기(요세푸스)]
맨 위 카드는 버리고, 다음 카드는 맨 아래로 보낸다.
q = [1, 2, 3, 4, 5, 6] while len(q) > 1: q.____(0) # (1) 버린다 q.append(q.____(0)) # (2) 맨 아래로 보낸다 print(q[0])
(1), (2)를 채우고 마지막에 남는 카드를 적어라.
8-3 [출력 예측 - 진법 변환]
큐에 든 자릿수를 10진수 값으로 만든다.
q = [1, 0, 2, 1] # 3진수, 앞이 가장 높은 자리 b = 3 t = 0 while len(q) > 0: t = b * t + q.pop(0) print(t)
출력을 적고 계산 과정을 쓰라.

2. 리스트 인덱싱과 슬라이싱

2-1 [출력 예측]
(1) 10 (2) 50 (3) 40 (4) 5 (5) IndexError
길이가 5면 유효한 인덱스는 0~4다. arr[len(arr)]은 항상 에러이고, 마지막은 arr[len(arr)-1] 또는 arr[-1].
2-2 [출력 예측 - 슬라이싱]
(1) [20, 30] (2) [10, 20] (3) [40, 50] (4) [50, 40, 30, 20, 10]
arr[1:3]에 3번 원소는 들어가지 않는다. 앞을 생략하면 처음부터, 뒤를 생략하면 끝까지. [::-1]은 뒤집기.
2-3 [출력 예측 - 리스트 메서드]
(1) [1, 2, 3, 4] (2) [0, 1, 2, 3, 4] (3) 4 [0, 1, 2, 3] (4) 0 [1, 2, 3]
pop()은 맨 뒤를, pop(0)은 맨 앞을 꺼내면서 지운다(꺼낸 값을 돌려준다). 이 네 개가 곧 스택과 큐다.
2-4 [출력 예측 - 반환값이 없는 메서드]
(1) [1, 2, 3] (2) None (3) [1, 2, 3]
arr.sort()는 arr 자체를 정렬하고 None을 돌려준다. 그래서 arr = arr.sort() 라고 쓰면 arr이 None이 되어버린다. sorted()는 원본을 두고 새 리스트를 돌려준다. append, insert도 None을 돌려준다.

(1) 0 (2) total + x (또는 total += x)
합의 시작값은 0이다. 곱을 누적한다면 시작값은 1이어야 한다.

(1) arr[0] (2) x > best
시작값을 0으로 두면 원소가 전부 음수인 리스트에서 답이 0으로 나와 틀린다. 첫 원소로 시작해야 안전하다.
3-4 [판단 - 무한 루프]
(B). n을 줄이지 않으니 n > 0 이 영원히 참이다.
while문 체크리스트: 조건에 쓰인 변수가 루프 안에서 바뀌는가? 안 바뀌면 무한 루프다. 재귀에서 기저 조건에 도달하지 못하는 실수와 같은 것이다.

4. 조건문과 논리 연산

4-1 [출력 예측 - if / elif / else]
A B C F
elif는 앞 조건이 거짓일 때만 검사하므로 n >= 80 은 사실상 80 <= n < 90 이다. 전부 if로 바꾸면 95점이 A, B, C에 모두 걸려서 마지막에 실행된 것이 반환된다.
4-2 [출력 예측 - and / or / not]
(1) False (2) True (3) False (4) True
and는 둘 다 참이어야 참, or는 하나라도 참이면 참. 파이썬은 0 < a < 10 처럼 이어쓰기가 된다(다른 언어에서는 안 된다).
4-3 [출력 예측 - 단락 평가]
(A) True - or는 왼쪽이 참이면 오른쪽을 실행조차 하지 않는다.
(B) IndexError - 왼쪽 s.pop()을 먼저 실행해 빈 리스트에서 pop한다.
위험한 연산 앞에 안전 검사를 먼저 둔다. and도 같아서 if len(s) > 0 and s[-1] == '(' 형태로 쓴다.
4-4 [출력 예측 - 빈 것은 거짓]
(1) False True (2) False True (3) False True
빈 리스트, 빈 문자열, 숫자 0이 거짓이고 나머지는 참이다. "0"은 비어있지 않은 문자열이라 참이다. 그래서 if len(s) == 0: 대신 if not s: 라고 쓸 수 있다.

5. 함수 (return의 의미)

5-1 [출력 예측 - print vs return]
10 (f1이 직접 찍은 것) / a = None / b = 10 / 11 / 그리고 (4)는 TypeError.
return이 없는 함수는 None을 돌려준다. 계산 결과를 다른 곳에 쓰려면 반드시 return을 써야 한다. f1(5) + 1 은 None + 1 이라 에러다.
5-2 [출력 예측 - return은 즉시 종료]
양수 / 여기 지나감 / 음수 또는 0
f(5)에서는 return을 만나는 순간 함수가 끝나서 print("여기 지나감")이 실행되지 않는다. return은 값을 돌려주면서 함수를 즉시 빠져나온다.
5-3 [빈칸 - 조기 반환]
(1) return True (2) return False (for문 밖, 함수 몸통 기준으로 들여쓰기)

9. 재귀

9-1 [출력 예측]
(1) 24 (2) 1 (3) 1
기저 조건을 n == 1 로 바꾸면 f(0)은 무한 재귀가 된다(0 -> -1 -> -2 -> ... 영원히 1에 도달하지 못한다). 그래서 n <= 1 이 더 안전하다.
9-2 [디버깅]
f1: 재귀 호출이 f1(n) 이라 인자가 줄지 않는다. f1(n-1) 로 고친다.
f2: 기저 조건 자체가 없다. if n == 0: return 0 을 넣는다.
고친 코드
def f1(n): if n <= 1: return 1 return n * f1(n-1) def f2(n): if n == 0: return 0 return n + f2(n-1)
9-3 [빈칸 - 유클리드 호제법]
(1) b == 0 (2) b, a % b
(48,18) -> (18,12) -> (12,6) -> (6,0) -> 답 6. 나머지 연산으로 값이 빠르게 줄어든다.
9-4 [트레이싱 - 중복 호출]
15번. (반환값은 5)
f(3)을 2번, f(2)를 3번 중복 계산한다. 이중 재귀는 같은 값을 여러 번 다시 계산해서 n이 조금만 커져도 폭발한다(f(30)이면 약 270만 번).
9-5 [전체 작성]
정답
def show_reverse(arr, n): if n == 0: return print(arr[n-1]) show_reverse(arr, n-1)
print를 재귀 호출 뒤로 옮기면 정방향(1 2 3 4)으로 출력된다. 가장 깊이 들어간 것부터 돌아오면서 실행되기 때문이다(호출 스택).
